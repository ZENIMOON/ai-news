## 🔴 Roblox × AI
### Studio MCP Serverが「Open Cloud」にアクセス可能に——開発者製品の設定やアセット取り込みをAIエージェントに直接依頼できる新ツール群を追加
- 情報源: https://x.com/RobloxCreators/status/2118110205724488083（Roblox公式X、一次情報） / https://devforum.roblox.com/t/studio-mcp-server-updates-open-cloud-access-in-your-mcp-client-and-asset-import-workflows/4975849（WebFetch不可のため検索結果上での内容確認） / https://github.com/JoCoding-Inc/roblox-skills/pull/39 / https://gamineai.com/blog/what-roblox-studio-mcp-open-cloud-access-changed-for-creators-2026
- 要約: Robloxが11月4日、Studio MCP Server（Claude Code/Cursorなど外部AIクライアントからStudioを操作する仕組み）に、Robloxの管理用Web API「Open Cloud」へアクセスできる新ツール`open_cloud_invoke`を追加した。これにより、AIエージェントへの指示だけで開発者製品（Developer Product）やゲームパスの設定変更、ゲーム設定の変更、分析データの読み取りなどが行えるようになった。API Key入力は不要で、Studio側が認証を仲介する設計。
- 要約: アクセス範囲はStudioの「MCP Permissions」タブで、ゲームごと・人ごとに細かく制御できる。既定ではほとんどの権限がオフで、Safe/Balanced/Full/Customのプリセットから選べるが、AIエージェント自身が権限を有効化することはできず、必ず人間がStudio側で操作する仕組みになっている点が複数ソースで一致している。データストアへのアクセスには別途「Studio Access to API Services」の有効化も必要。
- 要約: 同時に3つの新Skill（`rbx-open-cloud-usage`、`rbx-permissions`、`rbx-import-asset`）が追加され、特に`rbx-import-asset`はBlenderやMaya等からGLB/FBX形式で書き出したモデルを、確認を挟みつつStudioへ取り込める。
- **活用ポイント:** 「このゲームパスを追加して」「分析データを見て改善案を出して」のような運用系タスクをAssistant/Claude Codeに直接頼める範囲が広がった。ただしアップロードは取り消せずモデレーション対象になるため、Full権限を常時付けっぱなしにせず、作業内容に応じてCustomで必要な範囲だけ一時的に許可する運用が安全。

### 📚 テクニック: Assistantの挙動を独自の「Skills（創作者作成スキル）」でカスタマイズできる——CLAUDE.md的な運用をRoblox Studioで再現
- 情報源: https://devforum.roblox.com/t/assistant-updates-introducing-creator-authored-skills/4728447（WebFetch不可のため検索結果上での内容確認） / https://create.roblox.com/docs/assistant/skills
- 要約: これまでAssistantの「Skill」（特定の作業手順をAIに教えるガイド）はRoblox公式製のみだったが、クリエイター自身がMarkdownファイルで独自のSkillを書けるようになっている。Assistant Settingsの「Skills」タブから新規作成・編集・有効/無効の切り替えができ、Roblox公式のSkillを複製してカスタマイズすることも可能（複製後はRoblox側の更新が自動反映されないため、最新版が欲しい場合は複製し直す必要がある）。
- 要約: 作成したSkillはStudio内のAssistantだけでなく、Claude Desktop・Claude Code・Cursorなどの外部MCPクライアントからも同じ挙動として呼び出せる。独自Skill名に`rbx-`接頭辞は予約済みのため使用できない。
- **活用ポイント:** 「命名規則はこう」「このプレイスではUIはこの配色を使う」といったプロジェクト固有のルールをSkillとして書いておけば、Assistantに毎回説明し直す手間が減る。Claude Code等でのCLAUDE.md運用と同じ発想で、Robloxプレイス単位のルールブックをAI向けに作っておく習慣が有効。

## 🟢 周辺技術（3Dモデル生成など）
### 📚 テクニック: Nano Banana Pro / Seedream 4.0で、1枚のベーステクスチャから複数バリエーションを生成する「リテクスチャ」ワークフロー
- 情報源: https://www.scenario.com/blog/scaling-3d-asset-libraries-ai-retexturing / https://www.comfy.org/workflows/templates_3d_match_game_art_style.app-4075e779f621
- 要約: Scenario.ai等の解説によると、GoogleのNano Banana ProやByteDanceのSeedream 4.0は、既存の3Dモデルの参照画像とテキスト指示を組み合わせることで、同じメッシュに対してアルベド（基本色）・法線・ラフネス・メタリックといったPBRテクスチャの異なるバリエーションを連続生成できる。1つのベースアセットから「錆びた版」「光沢版」など複数の見た目を量産する用途で使われている。
- 要約: ComfyUIの公開ワークフローでは、Nano Banana Proにアウトライン参照画像とスタイル参照画像を渡すことで、3Dモデルのテクスチャとして使える2Dスプライトを生成する手順も公開されている。
- **活用ポイント:** Robloxで同じ形状の小物・プロップを複数の色違い・素材違いで量産したいとき、3Dモデル自体はBlenderMCP等で1つ作り、見た目のバリエーションだけを画像生成AIでテクスチャとして量産する分業が効率的。生成したテクスチャはDecalやSurfaceAppearanceとしてStudioに取り込む運用になる。
